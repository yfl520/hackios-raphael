# 红米 K20 Pro 双系统安装与使用教程

适用机型：Redmi K20 Pro／raphael，Bootloader 已解锁。电脑使用 Windows 10／11 64 位。

酷安：你说喜欢是装的

本教程按实际操作顺序编写。首次使用先阅读第一至第五节；已经安装双系统，需要更新时直接阅读第六节；安装应用阅读第九、十节；需要救砖或线刷回官方系统，阅读第十三节。

## 一、先选对操作入口

| 你要做什么 | 打开哪个文件或选择哪项 | 数据影响 |
| --- | --- | --- |
| 第一次安装双系统 | 开始刷机.bat → 1 首次安装 | 清除 Android 用户数据，自行设置 iOS 容量 |
| 更新已有双系统 | 一键更新.bat，或开始刷机.bat → 2 | 保留现有分区大小、Android 数据和 iOS 数据 |
| 核对安装包是否完整 | 校验文件.bat | 只检查电脑文件 |
| 检查手机分区与已有安装 | 开始刷机.bat → 3 | 只读检查，结束后停留在临时 TWRP |
| 临时进入 TWRP | 开始刷机.bat → 4 | 临时启动，不替换手机的 recovery 启动入口 |
| 将 recovery 入口改成 TWRP | 开始刷机.bat → 5 | 保留 iOS 数据，但电源＋音量上会进入 TWRP |
| 恢复本机保存的 recovery 备份 | 开始刷机.bat → 6 | 只恢复所选启动入口，不恢复个人数据 |
| 重新写入配套 iOS 系统文件 | 开始刷机.bat → 7 | 检查并按需重写 System，保留 iOS 数据卷 |
| 继续本包中断的首次安装 | 开始刷机.bat → 8 | 会重新初始化 iOS 数据；需要原安装记录 |
| 删除 iOS 并还原 Android 容量 | 开始刷机.bat → 9 | 清除两套系统的用户数据 |
| 连接爱思 | 连接爱思.bat，或开始刷机.bat → 10 | 在 iOS 桌面运行连接功能 |
| 把电脑里的 IPA 安装到 iOS | IPA链接安装.bat | 生成局域网下载链接，配合巨魔使用 |

菜单输入数字后按回车。确认页输入 Y 表示同意执行，输入 N 取消；输入容量时按页面要求填写整数，输入 Q 取消。已有双系统不要重复选择「首次安装」。

## 二、安装前准备

### 2.1 手机与电脑

1. 确认手机型号为 raphael，Bootloader 已解锁。本包不提供解锁功能；线刷工具中不要选择重新锁定 Bootloader。
2. 手机电量充至 25% 以上。电脑接通稳定电源，安装期间避免休眠。
3. 备份手机中的照片、文件、聊天记录和账号资料。**首次安装会清除 Android 用户数据，移除 iOS 会清除两套系统用户数据。** 安装脚本保存的分区备份不能还原被格式化的个人文件。
4. 建议电脑预留约 10 GiB 可用空间，用于解压、安装记录和分区备份。可选备份空间不足时会警告并跳过；安装所需临时文件仍必须有可用空间。
5. 只连接这一台手机，使用可传输数据的数据线，尽量直接连接电脑 USB 接口。
6. 不需要另装 Python、ADB 或 Fastboot，包内已经提供。正常使用文件选择器和 IPA 链接工具不需要管理员权限。
7. 不要求在 Android 安装 Magisk 或取得 root。自动提取本机无线数据在临时 recovery 中完成。

### 2.2 解压与文件校验

1. 在电脑上新建一个空文件夹，将压缩包**完整解压**到里面。不要在压缩软件窗口中直接运行，也不要覆盖解压到旧包目录。
2. 打开解压后的主目录，应能看到「开始刷机.bat」「一键更新.bat」「连接爱思.bat」「IPA链接安装.bat」「校验文件.bat」，以及 images、tools 等目录。
3. 双击「校验文件.bat」，等待检查结束。应看到「包内……个文件完整性检查通过」。
4. 如果提示文件缺失、被修改或有额外文件，先按提示核对目录。干净重新解压可以恢复原始文件；不要修改 manifest.json 绕过检查。
5. 自行下载的 IPA 建议保存在安装包目录外，例如电脑「下载」目录。IPA 工具可以选择任意目录中的文件；向包内添加文件可能影响整包完整性检查。

以后产生的 session-private 是本机安装记录和恢复材料，不要删除或与别人的记录混用。需要重新解压时使用另一个空目录，原目录及其 session-private 先保留。

分区备份属于尽力保存项：读取失败、保存失败或备份空间不足时，程序会明确警告并继续安装，不要求再次确认。state.json 的 backup_failures 会记录缺失项。**没有成功保存的备份就不能用于恢复，安装脚本也不能恢复已格式化的个人资料。** 操作状态记录及本次分区方案仍须能在电脑保存，才能执行和续装；这不等于必须有完整分区备份。

### 2.3 让电脑识别手机

可以从 Android 或 FASTBOOT 开始安装，任选一种。

**从 Android 开始：**

1. 在 Android 开启「开发者选项 → USB 调试」。不同 ROM 的设置位置可能不同。
2. 数据线连接电脑，解锁手机。出现「允许 USB 调试」时，核对为自己的电脑并选择允许。
3. 保持手机解锁，再运行安装入口。仅打开 USB 调试开关但没有确认电脑授权，仍可能无法连接。

安装器会先启动电脑本地 ADB 服务，再识别手机。若这台电脑已获授权，ADB 状态为 device，就不会再次弹出授权框；状态为 unauthorized 才需要在手机上确认。不要仅凭“没弹窗”判断连接失败。

**从 FASTBOOT 开始：**

1. 正常关机。
2. 按住电源＋音量下，直到出现 FASTBOOT 兔子画面。
3. 接好数据线，再运行安装入口。

如果电脑识别不到，先按第十二节排查数据线和对应模式的驱动。手机在 Android、FASTBOOT 和苹果 USB 模式时，电脑识别到的接口不同。

### 2.4 手机装过 Windows 双系统时

这里指手机自身安装过 Windows，不是电脑安装了两套系统。

1. 当前安装器支持匹配的 Android 静态／动态分区布局，尚不支持保留手机上已有的 Windows／UEFI 多系统布局。
2. 检测到 Windows、Microsoft 保留或恢复分区、EFI 系统分区及部分常见名称时，程序会停止，并在本轮 runlogs 中保存 partition-layout.json。不会自动删除 Windows、挪用其空间或覆盖启动入口。
3. EFI 分区只说明存在第三方引导，不能单凭它确定安装的是 Windows；程序仍会停止，等待核对具体方案。
4. 如果需要退出手机 Windows 双系统，应按该方案自己的还原说明恢复本机 Android 分区及引导，再核对布局。只刷普通官方 ROM 不一定恢复 GPT，不能直接认为已经还原。
5. 识别依据是当前读取到的 GPT 类型及名称，无法保证发现所有改名、残留或其他 LUN 上的 Windows 方案。安装过这类方案时应先说明，不能因为没有检测提示就认定可以保留 Windows 安装。

## 三、设置 iOS 分区大小

容量在「1 首次安装」过程中填写，已有双系统更新不会再次要求设置。

1. 等脚本读取这台手机的实际分区，显示「可选 ……～…… GiB」范围。
2. 根据自己的需要填写范围内的整数。例如想分配 48 GiB，就输入 48 后按回车。**没有默认的 20 GiB，直接回车会要求重新输入。**
3. 下限为 20 GiB；上限以这台手机当时显示的数值为准，脚本至少为 Android 保留 8 GiB。不要照搬别人手机的上限。
4. 查看确认页的 Android 剩余容量、iOS 总分区大小和 iOS 数据卷大小，再决定是否输入 Y。

userdata 不必位于磁盘末尾。程序从 userdata 自身的尾部划出所选空间，不使用整盘剩余容量计算上限；其后已有的分区及空闲区域保持原样。移除 iOS 时也只合回紧邻的 darwin 范围，不把后面的其他分区并入 Android。Windows／EFI 多系统布局仍按 2.4 节处理。

iOS 总分区中约 7.79 GiB 用于系统、启动资源及预留区域，其余用于 iOS 数据。举例：分配 32 GiB 后，iOS 数据卷约为 24.21 GiB。实际数值以确认页为准，分区会按 2 MiB 对齐。

安装后无法用本包直接无损调整容量。需要更改大小时，先自行备份两套系统的个人资料，再移除 iOS、重新首次安装；这两项操作会清除相关用户数据。

## 四、首次安装：从连接到进入 iOS

### 4.1 开始安装

1. 按第二节完成备份、解压、校验和设备连接。
2. 双击「开始刷机.bat」。在菜单输入 1，按回车。
3. 等待脚本检查机型、Bootloader、电量和分区，并临时进入 TWRP。脚本自动识别静态或动态分区布局，不需要自己猜测并更换 TWRP。
4. 安装过程中看到 TWRP 是正常流程。**不要自行点击格式化、改变分区、滑动修改系统或重启。** 需要操作时以电脑窗口的明确提示为准。
5. 按第三节填写 iOS 容量。脚本会先保存本机安装材料并读取无线数据，再显示安装确认方案。
6. 阅读数据清除范围和确认页。官方静态布局如果需要处理 Android 自动恢复 recovery 的机制，也会在这里说明；识别或准备失败时只警告后继续，返回 Android 后 iOS 启动入口可能被官方恢复。确定接受后输入 Y，按回车；取消则输入 N。

### 4.2 等待写入和校验

1. 让脚本完成分区、Android 数据初始化、iOS 系统和资源写入、iOS 数据卷初始化、recovery 写入及校验。
2. 期间可能多次切换 FASTBOOT 与 TWRP，窗口也可能暂时停留在校验步骤。保持 USB 连接和电脑运行，不要手动打断。
3. 本机无线数据由脚本自动提取，无需自己找分区、复制文件或修改 system.apfs。提取失败时，程序会提示功能可能缺失并继续安装，处理方法见第七节。
4. **以电脑窗口明确显示「安装完成，写入内容与边界检查通过」为成功依据。** 手机暂时显示 TWRP、进度条仍在移动，均不能单独说明安装成功。
5. 如果窗口显示「已停止」，先保留整个安装目录和报错内容，按第十二节处理。不要反复选择首次安装。

### 4.3 完成后启动

1. 看到「现在进入 iOS？输入 Y」时，输入 Y 后按回车。
2. 等待手机经过引导画面和苹果标志，进入锁屏或桌面。首次启动需要初始化数据，可能比后续启动慢；保持供电，不因短时间停留在苹果标志就立即重复刷写。
3. 如果没有输入 Y，手机会停留在临时 TWRP，不会倒计时自动启动 iOS。
4. 进入 iOS 后解锁，先确认触摸和电源键可用，再到「设置 → Wi-Fi」连接网络，用 Safari 打开网页检查联网。
5. 安装目录中的 session-private 保留在电脑上，用于中断续装、恢复入口及排查问题。不要压入共享给其他人的安装包。

## 五、日常切换 Android、iOS 与 FASTBOOT

| 要进入哪里 | 关机后的操作 |
| --- | --- |
| Android | 正常按电源键开机 |
| iOS | 电源＋音量上，通过本包的 recovery 启动入口进入 |
| FASTBOOT | 电源＋音量下，看到兔子画面后松开 |

**从 iOS 切回 Android：** 打开「设置 → 通用 → 关机」，滑动关机；完全关机后正常按电源键开机。

**从 Android 切回 iOS：** 在 Android 正常关机；完全关机后按电源＋音量上进入本包入口。

需要刷写或更新时，也先在正在运行的系统中正常关机，再进入 FASTBOOT。iOS 的数据卷仍在使用时，不要直接运行分区写入操作。

如果电源＋音量上进入的是 MIUI Recovery 或 TWRP，说明 recovery 启动入口与预期不同。选项 5 会主动把它替换成 TWRP；官方 ROM 也可能恢复原 recovery。按第十二节检查，不要将擦除数据当作切换系统的方法。

## 六、已有双系统怎样更新、续装和移除

### 6.1 保留数据更新

1. 先备份重要个人文件，完整解压要使用的包并校验。
2. 手机在 iOS 时，通过设置正常关机，再按电源＋音量下进入 FASTBOOT；也可以回到 Android，开启并授权 USB 调试。
3. 双击「一键更新.bat」，或运行「开始刷机.bat」并选择 2。
4. 核对确认页。此入口检查并按需更新配套 System、每机资源和 recovery，重新提取本机无线数据，保留现有容量和两套系统的数据。
5. 输入 Y 后等待写入与校验完成。看到成功提示后，按窗口提示选择是否启动 iOS。

更新不需要重新选择容量。不要为更新选择「1 首次安装」；也不要用另一台手机的资源或 session-private 替换自己的记录。

### 6.2 首次安装中断后继续

1. 保留原先执行安装的目录，尤其是 session-private，不要覆盖或删除。
2. 记录电脑窗口最后的错误和手机当前画面，先解决断线、驱动或空间不足等原因。
3. 需要继续时，从原目录运行「开始刷机.bat」，选择 8。
4. 脚本只有找到本机未完成的安装记录、且分区与记录匹配才会允许续装。
5. 阅读确认提示：**续装会重新初始化 iOS 数据；Android 格式化若尚未完成，也会重新格式化 Android 数据。** 接受后输入 Y。
6. 如果提示没有匹配记录，停止操作。不要借用别人的记录，也不要盲目重新分区。

### 6.3 移除 iOS、恢复 Android 容量

1. 先导出两套系统中需要保留的个人资料。**此操作会清除 Android 和 iOS 用户数据。**
2. 手机正常关机后进入 FASTBOOT，连接电脑。
3. 运行「开始刷机.bat」，选择 9，阅读删除范围后输入 Y。
4. 等待删除 iOS 分区、恢复 Android 容量、格式化数据及恢复匹配 TWRP 完成。
5. 完成后按窗口提示输入 Y 启动 Android；其他输入会停留在临时 TWRP。

移除完成后 recovery 是匹配的 TWRP。此操作不会自动把手机完整线刷成官方 ROM，也不能恢复已经清除的个人数据。

## 七、无线数据自动提取：需要做什么

首次安装和保留数据更新都会自动读取当前手机的 modemst1、modemst2、fsg、fsc，校验后生成这台手机专用的无线资源。读取在临时 recovery 中完成，不要求 Android 已取得 root，也不需要手动修改镜像。

IMEI 使用目标手机自身的设备数据，ICCID 由当前插入的 SIM 读取。提取材料保存在本机安装目录的 session-private；不要分享这个目录或用其他手机的目录代替。

**如果提示提取失败或无线功能缺失：**

1. 安装流程可以继续，但 Wi-Fi、SIM 识别或蜂窝功能可能无法使用；提取失败后不能保证无线正常。
2. 保留窗口提示和 session-private，先排查数据线、recovery 连接及分区读取错误。
3. 解决读取问题后运行「一键更新.bat」重新提取，不必为重新提取选择首次安装。
4. 不要下载别人的 NV 替换，也不要把空文件写回手机原始无线分区。

手机能显示 LTE、设备信息或运营商，只能用于检查对应状态；是否能完成某项通信操作，应以实际使用结果为准。检查蜂窝上网时，先确认本机 SIM 在 Android 中能够正常联网；进入 iOS 后，到「设置 → 蜂窝网络」打开蜂窝数据，关闭 Wi-Fi，再用 Safari 搜索新关键词并打开网页结果。以新网页能否加载判断联网，不只看 LTE／4G 图标。蜂窝数据不可用时可先使用 Wi-Fi；通话、短信和飞行模式恢复需要分别验证。

使用互联网 IPA 直链时，手机可以通过可用的 Wi-Fi 或蜂窝数据下载；使用电脑生成的局域网 IPA 链接时，仍须按第十节让手机和电脑连接同一局域网。仅开启手机蜂窝数据不能访问电脑的内网地址。

## 八、连接爱思助手

### 8.1 连接步骤

1. 在电脑安装爱思所需的苹果 USB 驱动，确认 Apple Mobile Device 服务可运行。
2. 手机进入 iOS 桌面，保持解锁亮屏，连接数据线；电脑打开爱思。
3. 双击包内「连接爱思.bat」，等待窗口完成接口切换和苹果设备识别。
4. 手机出现「信任此电脑」时选择「信任」，并按系统要求输入密码。已经配对过的电脑可能不再重复弹窗。
5. 窗口显示「本机已被 Apple Mobile Device 服务识别」后，在爱思中查看设备连接状态。
6. 连接成功后可以关闭脚本窗口，连接不会因关闭脚本或达到三分钟而自动结束。
7. 拔线后需要重新连接时，先查看爱思状态；没有连上再运行本入口，不要同时重复开启多个连接窗口。

### 8.2 没连接上时

- 提示 Apple Mobile Device 服务未响应：先在爱思中检查苹果驱动和服务，再重试。
- 一直显示连接中：保持手机解锁，检查当前接口是否正确枚举；不要只因为没弹信任框就判断手机未连接。
- FASTBOOT 能识别而苹果接口不能识别：分别核对各自驱动。FASTBOOT／调试接口使用兼容 WinUSB 的驱动，苹果接口使用苹果驱动，避免把所有模式一律替换成同一种驱动。
- 爱思已显示设备但实时屏幕不可用或部分信息缺失：不要因此重复分区或清空手机。爱思中的「已激活」显示也不能作为 Apple 官方激活状态的证明。

## 九、安装巨魔 Lite

### 9.1 用 Sileo 安装

1. 让 iOS 通过 Wi-Fi 或可用的蜂窝数据联网，用 Safari 打开网页确认可以联网。
2. 打开 Sileo，等待软件源刷新结束。
3. 进入「软件源」，点编辑／添加软件源，输入以下完整地址，确认添加后刷新：

```
https://byg.iosios.net/
```

4. 搜索 TrollStoreLite。若搜索结果使用中文名称，进入详情页核对包标识：

```
byg.iosios.net.trollstorehelper
```

5. 在包详情页选择安装／获取，加入队列后打开队列，确认执行。让 Sileo 一并安装该包声明的依赖。
6. 等待所有步骤完成。如果提示刷新图标缓存或重新载入，按 Sileo 提供的按钮操作。
7. 返回桌面，找到并打开 TrollStore Lite；看到安装菜单后，再按第十节安装 IPA。

软件源由第三方提供。打不开或搜不到包时，先检查手机网络、源地址与刷新结果；不要仅凭同名图标安装不明包。

### 9.2 找不到图标或安装失败

| 现象 | 操作 |
| --- | --- |
| 搜索不到包 | 核对完整源地址，刷新索引，再按英文名称搜索并核对包标识 |
| 依赖下载或安装失败 | 打开 Sileo 队列查看具体错误，检查网络，再重试失败项 |
| 队列中有包但桌面没有图标 | 确认已经执行安装并显示完成；仅加入队列不算安装成功 |
| 提示刷新图标缓存 | 使用 Sileo 提供的刷新入口，完成后返回桌面检查 |
| 巨魔能打开，文件选择为空或 Safari 分享无反应 | 直接使用第十节的 URL 安装方法 |

## 十、通过 URL 给巨魔安装 IPA

这里有两种方式：已有 IPA 直链时，在巨魔输入该链接；只有电脑里的 IPA 文件时，使用包内工具生成局域网链接。

### 10.1 已经有 IPA 直链

1. 打开 TrollStore Lite，点加号或安装菜单，选择「通过 URL 安装」「Install from URL」或「通过链接安装」。文字随应用语言而异。
2. 输入完整链接，保留 http:// 或 https:// 开头；检查没有空格、换行、中文标点或省略号。
3. 确认下载，等待巨魔解析文件，再按提示确认安装。
4. 显示安装完成后回桌面打开应用，检查是否能运行。

有效直链应能直接下载 IPA 文件。网盘分享页、项目首页、需要登录的网页和 GitHub Release 页面地址不能直接替代 IPA 下载地址。

从 GitHub 获取时，进入项目 Releases，找到需要的版本，展开 Assets，找到 .ipa 文件并复制该文件的下载链接。不要选择 Source code.zip，也不要复制页面顶部的网址。电脑能下载而手机访问不便时，用下面的局域网方式。

### 10.2 电脑已有 IPA：先选文件

1. 在电脑下载完整的 .ipa 文件，记住存放位置，例如「下载」。不要选 .zip 源码包、网页或下载未完成的临时文件。
2. 让手机和电脑接入同一个可信局域网。电脑通过网线连接路由器、手机连接该路由器的 Wi-Fi 也可以，只要二者能互通。
3. 双击「IPA链接安装.bat」。在 Windows 文件选择器中进入 IPA 所在文件夹，选中文件，点「打开」。**不用向黑色命令窗口里拖文件。**
4. 点「取消」会退出。选错文件或文件不合法时按窗口提示重新选择；工具会检查 IPA 中是否有 Payload 应用结构。
5. 若文件选择器打不开，按提示粘贴电脑上 IPA 的完整路径并回车，例如：

```
E:\下载\应用名称.ipa
```

6. 路径两端带双引号也可以。另一种启动方法是把 IPA 拖到「IPA链接安装.bat」这个**文件图标**上，而不是拖进已经打开的命令窗口。

### 10.3 选择与手机相通的网卡

1. 工具筛选已连接的物理网卡，优先排列有默认网关的地址。
2. 只有一个候选时自动使用；多个候选时，按网卡名称与 IPv4 地址判断，输入序号后按回车。回车可选第一个候选，但要确认它能与手机互通。
3. 不要选择虚拟机、VPN 或已断开的网络地址。电脑同时连着有线和 Wi-Fi 时，应选择手机能够访问的那一张。
4. 自动检测失败时，打开 Windows 当前网络的属性页，找到电脑的 IPv4 地址，按工具提示填写。应填写电脑地址，不是手机、路由器或公网地址，也不要填写 127.0.0.1 或 localhost。
5. 选好文件后，工具依次检查应用结构、读取网卡、读取并校验整份 IPA。读取阶段会显示进度条、百分比、已读大小、速度和预计剩余时间；大文件需要等待，不要重复启动工具。
6. 看到「当前应用：#编号 → 应用名称.ipa」和完整 http 地址后，核对文件名确实是准备安装的应用，再操作手机。

窗口地址类似下面这样，**此处仅为格式示例，不能照抄**：

```
http://192.168.1.23:8876/2
```

地址分为三部分：192.168.1.23 是电脑所选网卡地址，8876 是服务端口，最后的 2 是应用编号，不需要再输入 .ipa。三部分都使用电脑窗口实际显示的值。编号从 2 开始，1 保留不使用。

### 10.4 在手机输入并安装

1. 保持电脑服务窗口打开、电脑不休眠、手机仍连接可互通的 Wi-Fi。
2. Windows 如果询问防火墙访问权限，允许正在使用的可信专用网络。无需关闭整个防火墙。
3. 在手机打开 TrollStore Lite → 加号／安装菜单 →「通过 URL 安装」。
4. 输入电脑窗口显示的**本次完整链接**，从 http:// 一直到最后的短数字。不要只填 IP，不要漏掉 :8876，也不要使用 /1 或 /1.ipa。
5. 点确认后，电脑会显示向手机传输的进度条、已发送大小、速度和预计剩余时间。下载完成后继续等巨魔解析与安装，保持两端连接稳定。
6. 巨魔显示安装完成后，返回桌面打开应用。
7. 用完后在电脑服务窗口按 Q 或 Ctrl+C 结束，再按窗口提示关闭。关闭服务后，这条链接就无法下载；还要安装其他 App 时不用关窗口，按下一节换文件。

这个地址直接填入巨魔的 URL 输入框即可，不需要先用 Safari 下载、存储到「文件」或再分享到巨魔。

**电脑传输达到 100% 只表示这次文件发送结束，不代表巨魔已经安装完成。** 若手机分段读取，电脑可能分别显示多段传输；以巨魔的最终安装结果为准。工具尚未收到下载请求时只显示待操作提示，不会伪造下载进度。

### 10.5 换另一个 App 怎样操作

1. 等当前传输结束，在**原电脑窗口**按回车或 N，重新打开文件选择器；不用关闭工具。
2. 选择下一个 IPA，等读取校验进度完成。点「取消」会继续提供原应用。
3. 核对窗口「当前应用」后的文件名与编号。同一窗口的电脑 IP 和端口保持不变，手机输入框只需将末尾数字改为本次显示的编号。
4. **不同内容分配不同编号，同一内容保留原编号。** 例如第一次选 App A 是 /2，选择 App B 是 /3，再选同一份 App A 仍是 /2。两个 IPA 即使同名，只要内容不同也会区分。
5. 工具只提供当前选中的文件。切换后，上一个 App 的地址返回 404，不会把旧地址指向新应用。手机仍在传输时，工具会提示先等待结束，再按回车换文件。
6. 服务运行期间不要覆盖、移动或删除选定的 IPA。文件有变化时，按回车重新选择，等待校验后使用新编号。

编号记录保存在电脑的 %LOCALAPPDATA%\HackiOS\ipa-links.json，不放进公开安装包；重开工具或换用同一电脑上的另一份包时共用记录。不要删除或修改这份记录，以免复用旧编号。换电脑后编号可能不同，始终以该电脑窗口显示为准。

电脑换网、IP 地址变化或断网后，同样应关闭服务并重新运行，使用重新显示的地址。同一局域网中知道链接的人可以下载所选 IPA，用完及时结束服务。

### 10.6 用示例 IPA 练习

包内「应用安装」目录提供「示例应用.ipa」。第一次使用可以选择它，按上述步骤生成链接并在巨魔安装。示例的应用名称、来源与文件校验值见同目录的「来源与校验.json」。学会流程后，再重新选自己下载的 IPA。

## 十一、IPA 安装失败按这个顺序排查

| 现象 | 先检查什么 | 接下来怎么做 |
| --- | --- | --- |
| 服务窗口提示端口被占用 | 上一个 IPA 服务窗口是否还开着 | 关闭旧窗口，再运行工具 |
| 巨魔提示 404 | 是否用了旧链接、示例地址或输入漏字 | 核对电脑当前显示的完整地址，重新输入 |
| 提示 409 或文件已变化 | 服务启动后是否修改或覆盖了 IPA | 关闭服务，重新选择文件并使用新链接 |
| 提示 410 或文件不可用 | IPA 是否被移动、删除或安全软件隔离 | 恢复完整文件后重新选择 |
| 一直连接或下载不动 | 电脑窗口是否开着、是否休眠、网络是否互通 | 检查所选网卡、防火墙、VPN、访客 Wi-Fi 和 AP 隔离 |
| 显示「找不到应用包」或「Unable to locate app bundle inside the .IPA archive」 | 下载到的是 IPA，还是错误页、登录页或网盘网页 | 电脑重新下载完整 IPA，再用局域网链接安装 |
| 巨魔显示 301 | 先记录完整提示，核对文件和下载地址 | 此数值可能是巨魔错误码；按文件问题排查，不仅凭数字判断网络重定向 |
| 新选的 App 却像是旧 App | 核对「当前应用」文件名、编号及手机输入的地址 | 原窗口按回车重新选择，核对编号；必要时替换手机输入框中的整个链接 |
| 下载完成但安装失败 | 文件是否完整、是否损坏、应用要求的系统版本和架构 | 使用支持这套 iOS 环境的 IPA，按巨魔具体错误处理 |
| 安装完成却打不开 | 应用运行兼容性 | 先检查应用要求，不要因此重新分区或重装双系统 |
| Safari 分享到巨魔没反应或「文件」中找不到下载项 | 是否正在使用分享或文件导入路线 | 改用第十节的 URL 安装，无需继续操作分享页 |

局域网超时和互联网直链失效要分别排查。电脑提供的局域网链接不要求手机访问 GitHub，但手机仍需能通过局域网访问电脑。

## 十二、刷机及系统启动异常怎么处理

### 12.1 电脑完全识别不到手机

1. 先看手机实际画面：Android 桌面、FASTBOOT 兔子、TWRP、苹果标志或 iOS 桌面，使用对应操作入口。
2. 检查数据线是否支持传输数据，换一个电脑 USB 接口，尽量不用扩展坞。
3. Android 模式确认 USB 调试已开启、手机已解锁并允许这台电脑。
4. FASTBOOT 模式确认兔子画面还在，再检查设备管理器对应接口的驱动。
5. iOS 爱思连接按第八节检查苹果驱动与服务。先恢复连接，再考虑运行安装命令。

### 12.2 TWRP 分区空白、挂载失败或自动回 Android

1. 暂停手工操作，不要在 TWRP 中先点格式化，也不要随意换 recovery 镜像。
2. 查看电脑脚本是否明确提示「已停止」。如果已停止，保留最后报错与安装记录。
3. 本包按实际布局和 Data 策略选择 recovery；布局不支持、识别失败或临时 TWRP 启动失败时，需要先解决原因。
4. 仅仅看到 TWRP 的提示文字，不能代替电脑端写后校验结果。以本轮脚本是否完整成功为准。

### 12.3 停在苹果标志、黑屏或引导画面

1. 先确认电脑上是否已显示安装成功、是否已经输入 Y 请求启动 iOS。
2. 正在写入时不拔线、不强制重启。写入已结束但启动异常时，记录手机画面和最后的错误文字。
3. 保留原安装目录、session-private 及其中的 state.json，不要连续重复首次安装。
4. 首次安装确实中断时按第六节判断能否用选项 8；已安装系统需要更新时使用选项 2。
5. 镜像校验失败、GPT 不匹配、数据卷仍挂载和实际写入／读回失败需要先解决。分区备份失败仅警告后继续，两者不要混淆。

### 12.4 返回 iOS 却进了 MIUI Recovery 或 TWRP

1. 确认是正常关机后按电源＋音量上；电源＋音量下进入的是 FASTBOOT。
2. 回想是否执行过选项 5、恢复过 recovery 备份，或刷过官方 ROM；这些操作会影响 recovery 入口。
3. 使用本包选项 3 检查；它只读检查，结束后停留在临时 TWRP。
4. 需要重新部署本包入口时，按第六节使用选项 2 保留数据更新。不要把别人的 recovery 备份刷到自己的手机。

### 12.5 保存哪些材料方便排查

保留电脑窗口最后的完整错误文字、手机当前画面、执行的菜单项，以及原安装目录的 session-private。该目录可能包含设备身份、无线资源和配对相关信息；只向维护者提供需要的错误片段，不要把整个私人目录公开上传。

提示“Android 数据仍挂载”时，先停在当前 TWRP，不要手动格式化或强制卸载。程序必须确认数据卷正常卸载才能继续。使用配套数据卸载修复补丁时，关闭旧窗口，将四个文件覆盖到原目录，保留 session-private，再运行“校验文件.bat”和“开始刷机.bat”。若仅在卸载检查阶段停止、尚未修改分区，可按原计划操作；若已修改分区后中断，按第六节从原目录用选项 8 续装。仍报错时保留本轮 commands.jsonl 和 twrp-failure.log。

### 12.6 提示找不到 darwin

darwin 是本包存放 iOS 的分区。更新、重装、续装和移除要求它已经存在；这些操作不会把没有 iOS 的手机自动当成首次安装。

- 从未安装或已经完整移除：需要首次安装时选 1，确认会清除 Android 数据。
- 首次安装在分区创建前中断：保留原记录，确认未发生 GPT 写入后再选 1。
- 首次安装已经创建分区、写入中断：保留原目录及 session-private，修复连接后选 8。不要再次首次安装或手动格式化。
- GPT 主副表不一致、布局不明：先停止并保留日志，不能按上述普通中断方式盲目续装。

### 12.7 本地 ADB 服务连接失败／5037／10060／10061

出现 cannot connect to 127.0.0.1:5037、daemon still not running 等内容，说明电脑本地 ADB 服务未能正常响应，不能仅据此判断手机分区损坏。

本包在第一次识别手机前明确启动本地 ADB 服务，不依赖其他手机助手先运行。若旧脚本出现 cannot start server on remote host，请更新到配套修正版；手机可先保持当前 Android 或 FASTBOOT。服务恢复后，Android 已授权连接不会重复弹出 USB 调试授权框。未授权时保持手机解锁并选择允许。

1. 保留原安装目录和全部记录，先关闭其他手机助手、模拟器等可能占用 ADB 的程序。
2. 检查安全软件是否阻止包内 ADB 运行、本机 5037 端口是否被其他进程占用；必要时恢复电脑环境后重试。
3. 首次安装已经写入时，连接恢复后从原目录选 8。程序要求同一手机、匹配的 GPT 和原来的已授权操作记录；备份缺失或损坏只警告，不阻止续装。有可比对的 Android boot 指纹且发现已变化时仍停止。
4. 选 8 会重新初始化 iOS 数据；Android 尚未格式化完成时也会重新格式化 Android 数据。它不是保留首次安装途中个人数据的恢复工具。
5. 不要因为写入进度停止就反复选 1、强行终止 ADB 或删除 session-private。

### 12.8 分区读取不完整或静态 recovery 防覆盖未匹配

本包不要求 recovery 提供 shell_v2。旧版 ADB 也通过无终端的 exec-out 通道执行命令，单独记录错误信息及远端退出码。TWRP 启动期间可能切换 USB 模式并重建 ADB 连接；程序会等待同一手机的 TWRP、USB 配置与连接连续稳定约 5 秒，再进入后续检查。启动等待约 90 秒，期间仅重复固定的只读查询，不会自动重启或重放写入；若仍超时，保留完整命令日志与手机当前画面。

若旧包在 TWRP 刚启动时报“ADB 命令返回不完整”，请关闭脚本，将匹配的启动连接补丁覆盖到原安装目录，保留 session-private，再运行“校验文件.bat”和“开始刷机.bat”。仅启动查询中断且尚未分区的按原计划操作；已分区后中断的从原目录选择 8 续装。实际写入失败或写后读回不一致仍须停止，不能通过删除校验来继续。

- 分区读取错误：记录目标、偏移、应读与实际字节数。底层 dd 的退出状态和错误保存在 commands.jsonl。程序仅对短读取重读一次，不会自动重放写入；备份读取失败只警告、跳过该备份继续，实际分区识别、边界检查和写后读回失败仍会停止，不采用不完整数据。
- 静态恢复机制未匹配：程序会警告并跳过防覆盖继续安装，不猜测修改未知脚本。返回 Android 后 iOS 启动入口可能被还原，之后可能需要重新部署 recovery。保留 static-recovery-evidence.json 和当前 ROM 名称／版本，方便后续适配；该文件列出预期脚本、服务是否存在及可读取的相关 init 定义。防覆盖准备失败同样只警告；一旦开始实际写入，写入失败或读回不一致仍停止。
- GPT 错误：记录完整提示。程序会根据已验证表头读取有界范围，CRC、主副一致性、边界或重叠检查失败仍需停止；不能据此自行刷入别人的 GPT。

## 十三、救砖与线刷回小米官方系统

### 13.1 先判断能不能使用这条路线

本节使用 Windows 上的 MiFlash，通过 FASTBOOT 刷入匹配的官方完整线刷包，处理系统损坏、反复重启、无法进入 Android，以及需要退出双系统并恢复官方系统等情况。**手机必须能进入 FASTBOOT，并且 Bootloader 已解锁。** 不需要先进入 Android，也不要求 Android 的 USB 调试已开启。

| 手机当前状态 | 应当怎样处理 |
| --- | --- |
| 还能正常进入 Android 或 iOS | 先备份资料，再从系统内正常关机，按电源＋音量下进入 FASTBOOT |
| 卡在苹果标志、MIUI 标志、引导文字或系统已无响应 | 确认电脑不在写入后，长按电源＋音量下尝试进入 FASTBOOT |
| 能看到 FASTBOOT 兔子，但电脑识别不到 | 先按 13.5 修复数据线、USB 接口与 FASTBOOT 驱动，识别后再刷 |
| Bootloader 已锁定，提示不允许刷写 | 不能直接按本节强刷；满足小米官方解锁条件后再处理，或联系官方售后 |
| 只有黑屏，设备管理器显示 Qualcomm HS-USB QDLoader 9008 | 属于 EDL／9008 路线，不是本节的 FASTBOOT 操作；交由有合法授权的维修渠道处理 |
| 完全不通电、反复断连，或电脑没有任何 USB 设备变化 | 先排查充电、线材、接口与硬件，不能直接判定为系统故障 |

不要把“黑屏”直接等同于 9008，也不要为进入 9008 拆机短接或使用来历不明的引导文件。本节不包含 EDL 强刷或账号绕过。

### 13.2 数据、容量与原来的双系统入口

**以下按清空手机资料来操作，先导出 Android 和 iOS 中需要保留的照片、文件、聊天记录及账号凭证。** 不能用“保留用户数据”代替备份。手机已无法开机、资料无法导出时，需要先接受无法保留这些资料的结果，再决定是否继续刷写。

1. 记住原小米账号、密码及绑定手机号。刷后若要求验证原账号，应使用自己的账号完成验证；线刷不会替你解除账号绑定。
2. 把本机双系统安装目录及 session-private 留在电脑上。它们不是照片或聊天记录备份，也不要拿其他手机的同名目录替换。
3. 官方线刷会覆盖刷机脚本指定的系统和启动相关分区。按原 iOS 启动入口、第三方 recovery、Android root 及相关模块需要重新部署来准备；不要把旧模块直接恢复到新官方系统。
4. **只刷官方 ROM，不保证删除独立的 darwin 分区或还原改动过的 GPT，也不保证 Android 立即收回全部容量。** iOS 数据即使仍残留，也不能当成可用备份。
5. 如果只是要从本包双系统退出、当前布局仍能通过本包检查，可先按第 6.3 节使用选项 9 移除 iOS，再线刷官方。选项 9 会清除两套用户数据；检查不通过时停止，不要修改记录绕过检查。
6. 从第三方动态分区 ROM 返回官方时，先核对原 ROM 的“回官方／恢复原分区”说明。若它要求专用的恢复布局流程，普通官方线刷不能替代那一步。不要使用其他容量机型的 GPT，也不要手工删除不认识的分区。

分区状态不明、GPT 检查失败或刷机工具提示分区不存在／镜像超过分区大小时，保留错误与本机记录，先核对布局，不能靠反复点击刷机解决。

### 13.3 下载正确的官方线刷包

ROM 下载目录：[红米 K20 Pro／raphael 国行版 ROM](https://xiaomirom.com/rom/redmi-k20-pro-mi-9t-pro-raphael-china-fastboot-recovery-rom/)。该站是第三方索引，下载前仍需核对机型、地区和实际文件。

1. 打开上面的页面，找到“稳定版 → Fastboot 线刷包”。本节使用完整 Fastboot 线刷包，不使用 Recovery 卡刷包、OTA 增量包或第三方动态分区 ROM。
2. 核对设备代号是 **raphael**。Redmi K20 普通版等其他机型不能混用；同为 raphael 的不同地区设备也要核对原销售地区，不能仅凭外观或代号选择国行 ROM。
3. 该链接是中国大陆版本目录。原设备为国际、欧洲、印度等地区版本时，应另找匹配地区的官方包；不要照搬中国版文件。
4. 认清文件类型：本节下载的文件通常以 **raphael_images_** 开头、以 **.tgz** 结尾。以 miui_RAPHAEL_ 开头的 .zip 通常是卡刷包，不能直接交给 MiFlash；把扩展名改成 .tgz 也不会变成线刷包。
5. 例如国行页面列有 V12.5.6.0.RFKCNXM 的完整线刷包。这只是核对文件形式的例子，不代表适合所有地区或所有改动过布局的手机；不要为使用示例而强行降级。
6. 等待下载完整。页面若提供校验值，用相同算法核对；解压软件提示文件损坏或意外结束时，重新下载，不要忽略错误继续刷。

### 13.4 准备 MiFlash 与解压目录

小米官方操作说明：[小米帮助中心：如何刷机](https://www.mi.com/service/support/rom/)。MiFlash 工具可从该帮助页的下载入口获取；也可查阅 [MiFlash 下载目录](https://xiaomirom.com/download-xiaomi-flash-tool-miflash/)。后者是第三方索引，并非小米官网；其中的旧链接可能失效，不要仅凭“官方最新版”的站点标题判断来源。MiFlash 和官方 ROM 需要自行下载，不包含在本双系统安装包中。

1. 在 Windows 电脑准备 MiFlash、小米／Android Bootloader 驱动，以及能解压 .tgz 的压缩软件。工具若为安装版，按其安装提示操作；若为便携版，完整解压后运行其中的 XiaoMiFlash.exe。
2. 将官方 ROM 解压到本地磁盘的短英文路径，例如 D:\ROM\raphael。路径尽量不用空格、中文、特殊符号，也不要放在压缩软件临时目录、网盘同步目录或手机存储中。
3. .tgz 可能先解出 .tar；如果得到的仍是单个 .tar，再解压一次，直到看到刷机文件夹。
4. 正确的 ROM 根目录应当同时包含 **flash_all.bat**、**images 文件夹**等文件。MiFlash 需要选择这一层，不能选择外层压缩包、空文件夹或里面的 images 子目录。
5. 给 ROM 压缩包、解压文件及刷机日志预留足够空间。保持电脑供电，暂时关闭自动休眠，让手机有足够电量，尽量充至 50% 以上。
6. 关闭双系统安装窗口、爱思连接窗口，以及其他正在访问手机的工具。只连接准备刷写的这一台手机。

解压结果可以按下面的示例检查。文件夹名称可以不同，关键是选择含 flash_all.bat 的那一层。

```
D:\ROM\raphael\
    flash_all.bat
    flash_all_lock.bat
    images\
        boot.img
        ...
```

**不要双击 flash_all_lock.bat，也不要使用任何包含重新锁定 Bootloader 操作的脚本。** 本节在 MiFlash 中操作，不需要手动执行这些 .bat。

### 13.5 进入 FASTBOOT 并让电脑识别

1. 手机还能操作时，从系统内正常关机。已卡死时，先确认电脑没有正在刷写，再长按电源＋音量下，直到看到 FASTBOOT 兔子画面。进入后松开按键，不要一直按住电源键让它再次重启。
2. 使用能传输数据的数据线直接连接电脑 USB 接口，尽量不经过扩展坞；识别不稳定时换线、换电脑上的其他接口。
3. 在 Windows 设备管理器中找到这台手机，正常的 FASTBOOT 接口通常显示 Android Bootloader Interface 或同类名称。黄色感叹号、未知设备或错误的接口驱动，需要安装匹配的 Bootloader 驱动；FASTBOOT 不使用爱思的苹果驱动。
4. 打开 MiFlash，点“刷新／refresh／加载设备”。列表应出现本机设备标识。**列表为空时先解决识别问题，不要直接点击刷机。**
5. 需要进一步确认时，在本双系统包的 tools\platform-tools 文件夹打开 PowerShell，执行下面两条只读命令：

```
.\fastboot.exe devices
.\fastboot.exe getvar product
```

6. 第一条应列出设备标识及 fastboot；第二条应返回 product: raphael。设备不符时停止。若命令停在 waiting for device，按 Ctrl+C 结束等待，继续检查线材、USB 接口与驱动。
7. 命令提示找不到 fastboot.exe 时，检查是否真的在含该文件的目录执行，不要把这类路径错误当成手机故障。完成查询后关闭额外命令窗口，回到 MiFlash。

手机正常进入 FASTBOOT 时，不需要开启 Android USB 调试，也不需要等待 iOS 的“信任此电脑”弹窗。若刷官方后 TWRP 自动重启回 Android，不要反复刷入不同的 TWRP；MiFlash 走 FASTBOOT，不要求先启动 TWRP。

### 13.6 MiFlash 选择路径和清除方式

1. 打开 MiFlash，点“选择／select／浏览”，选择 13.4 中解压好的 ROM 根目录，例如 D:\ROM\raphael。
2. 再次刷新，确认列表中的设备是当前这一台手机，且手机仍停在 FASTBOOT。
3. 在窗口底部明确选择 **全部删除／clean all**。本节用于清空恢复官方，不选择“保留用户数据／save user data”。
4. **不能选择“全部删除并 lock／clean all and lock”。** 部分版本默认勾选带 lock 的选项，每次重新打开工具或切换 ROM 后都要重新看清楚，不能只依赖上次选择。
5. 若界面显示将运行的脚本，确认是 flash_all.bat，不能是 flash_all_lock.bat。工具没有显示脚本名称时，至少确认底部清除选项的完整文字；选项含义不清楚就先不要点击刷机。

| MiFlash 选项 | 本节是否使用 | 含义 |
| --- | --- | --- |
| 全部删除／clean all | 使用 | 清除用户数据，按对应脚本刷入官方系统，保留 Bootloader 解锁状态 |
| 保留用户数据／save user data | 不使用 | 不能作为双系统或不同布局之间保数据恢复的方案 |
| 全部删除并 lock／clean all and lock | 禁止选择 | 清除数据后重新锁定 Bootloader，错误机型、地区或布局下可能导致无法启动 |

本节目标是恢复官方并保持解锁，后续还要安装双系统时同样不应重新锁定。不要另行运行 fastboot oem lock、fastboot flashing lock 或其他锁定命令。

### 13.7 开始刷写与首次开机

1. 点击“刷机／flash”前最后核对：机型和地区匹配；ROM 完整且目录正确；本机 FASTBOOT 已识别；选择的是“全部删除”；已备份并接受清除数据。
2. 点击一次“刷机／flash”，等待工具执行。刷写过程中不拔线、不关闭程序、不让电脑休眠，也不再启动其他刷机或连接工具。
3. 等待结果列出现 success／成功，并查看状态中是否仍有失败项。只看到绿色进度条走动、传输结束或手机重启，不等于整轮已经成功。
4. 按工具结果等待手机自动重启。首次 MIUI 启动通常比日常开机慢，先给它约 10～15 分钟观察；这不是固定超时判据，仍需结合工具日志和手机是否循环重启判断。
5. 进入欢迎设置页后，完成语言、网络与原账号验证。刷机后的激活验证请使用本人的小米账号和 Google 账号，不能通过再次清除数据绕过。
6. 能到欢迎设置页或桌面，说明 Android 已能启动；是否恢复到预期分区与容量，还要继续检查 13.8。

若工具红字报错，先记录第一处失败命令、完整错误和当前手机画面。工具已经停止后，再按 13.9 判断；仍在写入时不要因为等待较久就强制断电。

### 13.8 刷完后检查，确认恢复到什么程度

1. 在 Android 完成初始设置，检查触摸、电源键、充电、Wi-Fi、蓝牙和 SIM 网络是否正常。系统设置中的机型与版本应是刚刷入的官方 ROM。
2. 在“设置 → 关于手机／存储空间”检查容量。可用空间本来就会扣除系统占用，不能直接和宣传容量逐字比较；重点看是否仍异常缺少原先分给 iOS 的大块空间。
3. 如仍有 darwin 分区、容量明显异常，或工具报告分区布局不匹配，说明恢复工作尚未完成。保留本机 session-private、MiFlash 日志及当前分区信息，核对本机原始布局或原动态 ROM 的回官方方案。
4. 不要为修容量直接套用网上的通用分区表、其他手机备份，或反复格式化 userdata。格式化文件系统不能保证还原被改动的分区边界。
5. 官方 ROM 可能恢复官方 recovery，原电源＋音量上进入 iOS／TWRP 的入口可能因此失效。需要重新安装双系统时按 13.10 操作，不要把入口消失误判成 iOS 自动恢复失败。

### 13.9 常见报错与处理顺序

| 报错或现象 | 先做什么 | 不应怎样处理 |
| --- | --- | --- |
| MiFlash 列表为空，或 waiting for device | 确认兔子画面、换数据线／接口，检查 Bootloader 驱动，再刷新 | 不用爱思的“信任”流程解决 FASTBOOT 识别 |
| can not found file、找不到脚本或镜像 | 检查是否完整解压两层，所选目录是否同时有 flash_all.bat 和 images | 不选 images 子目录，不改后缀伪装线刷包 |
| mismatching image and device、product 不匹配 | 核对设备代号、地区及 ROM 文件，换正确的包 | 不删除机型检查，不修改脚本强刷 |
| Flashing is not allowed in Lock State、设备未解锁 | 停止，按小米官方规则处理 Bootloader 解锁或送修 | 不靠重复刷写、格式化或 9008 绕过限制 |
| antirollback check error、反回滚错误 | 停止，核对当前固件与所选版本，选择符合要求的官方包 | 不删反回滚检查，不强行降级 |
| 分区不存在、镜像超过分区大小、GPT／布局报错 | 保留完整错误，核对原动态 ROM 的恢复布局流程与本机分区记录 | 不随意删 super、darwin、persist 或未知分区 |
| Write failed、USB 传输失败、设备断开 | 记录失败位置，待工具停止后检查线材、USB、供电和驱动，恢复稳定识别再决定重试 | 不在写入中拔线，不同时运行多套刷机工具 |
| 提示 check point／检查点错误，但手机已启动 | 查看日志中的第一处失败：若镜像写入报错，按失败处理；若仅是末尾锁定检查报错且全部写入完成，继续核实系统和解锁状态 | 不为消除末尾报错改选“全部删除并 lock” |
| 显示成功，但长时间停在 MIUI 标志或反复重启 | 留下日志，确认等待时间、ROM 匹配和布局；必要时回 FASTBOOT 重新排查 | 不立即再刷不匹配的 TWRP，不盲目连续格式化 |
| 刷后要求原小米／Google 账号 | 用本人原账号完成验证，遗忘时使用官方账号找回 | 不使用绕过激活或借用他人账号的工具 |
| 黑屏且只出现 9008 端口，无法进入 FASTBOOT | 保存设备管理器信息与刷机记录，转有授权的维修渠道 | 不把本节步骤当成 EDL 教程，也不下载随机 firehose 强刷 |

求助时提供：手机型号与地区、ROM 完整文件名、MiFlash 版本、所选清除选项、第一处错误和手机当前画面。设备标识、IMEI、账号、配对材料及私人备份不要公开上传。

### 13.10 恢复官方后重新安装双系统

1. 先完成官方 Android 的初始设置，并按 13.8 确认存储容量、Wi-Fi、蓝牙与 SIM 网络；有异常先解决，不带着原问题继续分区。
2. 确认 Bootloader 仍已解锁。在 Android 开启开发者选项与 USB 调试，连接电脑并允许本机调试授权。
3. 将双系统一键包重新完整解压到新的空目录，先运行“校验文件.bat”。不要覆盖到旧包，也不要把他人 session-private 或 NV 数据放进来。
4. 按本教程第一至第四节进行首次安装，自行设置本次 iOS 容量。无线数据由脚本从当前这台手机读取，不需要借用别人的 IMEI、ICCID 或无线备份。
5. 让本包按实际布局选择 recovery。官方静态布局、第三方动态布局不能只看自己手头 TWRP 的文件名来判断；出现布局不支持或挂载失败时先排查，不手工交替刷入动态／静态 TWRP。
6. 安装完成并确认两套系统能正常启动后，再按需要安装包内的「红米双系统进入苹果模块（蜂窝上网版）.zip」、Sileo 软件和巨魔。模块 ZIP 在 Android 的 Magisk／KernelSU 管理器中安装，详细步骤见包内「进入苹果模块使用说明.md」。不要直接恢复旧系统上的 root 模块或其他手机的启动备份。
